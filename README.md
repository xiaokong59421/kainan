凯南恋爱聊天风格是一个独立的 Codex Skill。它提炼的是可观察的表达和教学特征，不代表或冒充真实创作者、官方团队或任何课程；它也不承诺某句话能让特定的人爱上你、回头或改变选择。

它关注的不是背诵“必杀话术”，而是把用户真实想说的话调整到合适的场景、节奏和落点：先看对方实际说了什么，再给一条能发的话，最后说明积极、模糊、冷淡或拒绝时怎么收住。

## 它能帮你解决什么

| 你遇到的问题 | 凯南 Skill 会怎么帮 |
| --- | --- |
| 不知道这句话怎么回 | 第一屏先给一条不超过两句的可发送版本，再补一句理由和后续分支 |
| 聊天像查户口、没有情绪 | 从当下场景取材，用轻问句、反差、回调或适度自嘲创造来回 |
| 想推进关系或提出邀约 | 按初识、暧昧、稳定关系分别调整主动度，给低压力、可拒绝的下一步 |
| 对方回复变短、变慢或回避 | 区分看得见的行为、暂定解释和未知，不靠秒回、表情或性别读心 |
| 想表达“我喜欢你什么” | 用具体观察和相处感受表达，不用空泛外貌夸奖或一辈子承诺 |
| 想判断“正缘还是孽缘” | 改看安心程度、双向投入、冲突修复和边界保留，不做命定结论 |
| 想像直播或课程一样复盘 | 用“先判断信号—再解释机制—给替换句—演练分支”的教学节奏 |
| 想要微信副驾的结构化结果 | 明确要求 JSON 后，只输出固定字段和三种不同策略的短回复 |

## 风格能力地图

这套风格不是固定人设，而是一组可以根据用户本人和现场反馈调整的表达能力：

| 维度 | 可观察做法 | 不做什么 |
| --- | --- | --- |
| 接地气 | 说具体的人、事、时间和感受，少用空洞术语 | 不把复杂关系包装成玄学定律 |
| 有梗 | 从现场细节、反差、共同记忆和轻微自嘲取笑点 | 不拿外貌、创伤、隐私或性别刻板印象当笑料 |
| 平等 | 保留自己的时间、偏好和选择，也承认对方同等的选择权 | 不跪舔、不装忙、不用框架控制对方 |
| 骚而有度 | 在已有舒适感时加入轻微、可撤回的暧昧 | 不索要私密照、不露骨性化、不把沉默当同意 |
| 懂情绪 | 先回应感受，再询问对方想说还是想安静 | 不把“我没事”直接翻译成隐藏心思 |
| 重落地 | 每次收束到一句话、一个动作、一个观察窗口或停止条件 | 不承诺必然脱单、复合或让人上头 |

## 按关系阶段使用

| 阶段 | 目标 | 推荐动作 | 停止信号 |
| --- | --- | --- | --- |
| 初识 | 降低陌生感，找到共同语境 | 结合动态或当下场景开口；少量追问；自然收尾 | 明确不想聊、持续回避或要求停止 |
| 暧昧 | 检验互惠，增加共同体验 | 一次轻调侃接一句真诚；提出具体、低压力邀约 | 对方不接暧昧、转移话题或不给任何替代时间 |
| 稳定关系 | 表达具体喜欢，处理分歧 | 说可观察细节；讨论可执行的承诺和修复方式 | 威胁、控制、羞辱、暴力或持续越界 |
| 冷淡/拒绝 | 保持体面和安全 | 承认选择；最多留一次开放出口；停止追发 | 明确拒绝、要求不要联系或让人感到不安全 |

## 一个小例子

**对方：**“你怎么这么会聊？”

**可发送：**“主要是你接得住，不然我一个人也演不成双口相声。”

这句话把夸奖变成双向互动，保留一点玩笑但没有逼迫。如果对方继续接话，可以顺着共同场景聊；如果只礼貌回应或明显转冷，就回到普通话题或自然收尾，不把“不接梗”解释成欲擒故纵。

## 证据与来源

风格画像综合用户提供的本地逐字稿、用户补充的全平台观察，以及可公开检索的账号、视频标题和页面元数据。可直接观察的内容与搜索摘要、百科二手条目、转载课件和课程营销文案分开记录；不可达、登录墙或脚本壳页面保持未知，不用想象补全。

本仓库不包含本地 DOCX 原件、聊天截图、学员身份信息、未公开课程全文或账号凭据。公开来源只用于高层次风格归纳，不作为恋爱效果、心理诊断或官方归属的证明。完整范围和限制见[来源与证据说明](references/knowledge/来源与证据说明.md)。

## 安装

将下面的安装口令发送给你使用的 AI 助手：

```text
请将公开仓库 https://github.com/xiaokong59421/kainan 下载并安装为本地 Skill。
```

安装完成后，可以输入：

```text
请使用 $kainan-love-coach 分析这段聊天，先给一条能直接发送的话，再解释风格、后续分支和边界。
```

需要接入微信聊天副驾时，可以明确要求严格 JSON：

```text
请使用 $kainan-love-coach 读取下面的微信聊天，只输出微信副驾 JSON，不要输出 Markdown 或解释。
```

首次使用时，最好一起提供：

```text
任务：分析 / 改写 / 角色练习 / 教学复盘
原文：对方说了什么，我说了什么；必要时标出顺序和间隔
语境：怎么认识、当前关系阶段、最近发生的关键事件
目标：想推进、邀约、澄清、表达喜欢、修复，还是体面收线
边界：双方是否均为成年人，是否允许轻微调侃或暧昧
```

不知道的项目可以留空，也可以直接讲故事。截图只需提供完成任务所需的部分，并先遮盖姓名、头像、手机号、定位、单位和其他第三方隐私。年龄不明时只生成非性化表达。

## 一个典型回答如何产生

```text
用户请求
  → 确认任务、阶段、语境和边界
  → 锁定说话人，区分原文事实／暂定解释／未知
  → 读取当前问题需要的 1–3 份参考
  → 普通模式：生成可发送版本、拆解和后续分支
  → JSON 模式：生成固定字段、风险等级和三条短回复
  → 留下观察窗口和停止条件
```

Skill 不会替用户发送消息，不会直接读取、解密或导出微信、QQ等聊天软件数据库，也不会把明确拒绝当成需要破解的“测试”。遇到跟踪、威胁、暴力、性胁迫、诈骗或隐私曝光时，优先转入安全支持，而不是继续优化话术。

## 设计原则

1. **先理解原话，再调整表达。** 不把用户想说的内容替换成虚构人设。
2. **行为比标签可靠。** 不凭性别、星座、回复秒数、表情或“秘密清单”确定个体心理。
3. **有梗服务于来回。** 每次最多加入一个主要玩笑，笑点不能让对方承担羞辱或解释成本。
4. **暧昧必须可撤回。** 对方回避、拒绝、沉默或显得不适时，立即降级或结束。
5. **建议说明代价。** 轻松、推拉、节奏和包装都要结合关系阶段与长期信任讨论。
6. **明确拒绝不可绕过。** 目标不是“拿下某个人”，而是让用户更清楚、更体面、更有选择权。
